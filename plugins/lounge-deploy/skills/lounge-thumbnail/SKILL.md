# 라운지 작품 썸네일

현재 열린 작품 프로젝트를 기준으로 제작한다. Studio에서는 파일 트리가 프로젝트
디렉터리이며, 라운지 서비스 자체의 저장소와 학생 작품을 혼동하지 않는다.

## 작품 이해와 대화

- PROJECT.md와 README, 관련 화면·규칙 코드, 배경·캐릭터 에셋을 읽는다.
  문서와 구현이 다르면 구현을 기준으로 하고 미완성 의도만 사용자에게 확인한다.
- 작품명, 핵심 경험, 배경, 주인공의 외형·색·화풍, 참조 파일을 짧게 정리한다.
  파일과 이전 대화에서 알 수 있는 사실을 다시 묻지 않는다.
- 대표 장면을 제안하고 사용자의 강조점·수정을 반영한다. 방향이 충분하면 바로
  제작하며 매번 선택·승인을 반복하지 않는다. 상담만 요청했으면 생성하지 않는다.
- 실제 이미지 입력을 지원하면 기존 캐릭터·배경을 참조 이미지로 전달한다.
  파일명만 보고 외형을 보았다고 주장하지 않는다. 이미지 열람·참조가 불가능하면
  그 한계를 밝히고 필요한 이미지만 첨부받는다. 비밀값·개인정보는 전달하지 않는다.

## 제작 규격

- 기본 비율은 16:9다. 큰 작품명과 핵심 경험을 보여주는 대표 장면으로 구성한다.
  이는 제작 기본값이며 업로드 서버의 강제 규격이나 용량 제한을 뜻하지 않는다.
- 제목은 짧게 1~2줄, 배경과 대비를 확보하고 피사체와 겹치지 않게 배치한다.
  부제는 필요한 경우 한 줄만 쓴다. 작품명과 표지 문구가 다르면 의도를 확인한다.
- 핵심 행동·목적을 돌과 물결, 팽이와 게이지, 편집 화면처럼 구체적으로 보여준다.
  기존 캐릭터의 외형과 세계관을 유지하되 구도·조명·동작을 연출한다.
- 게임·체험은 대표 행동과 장면, 학습·서비스는 상징과 여백, 편집·도구는 실제
  기능을 보여주는 화면을 우선한다. 모든 작품에 같은 화풍·채도를 강제하지 않는다.
- 작품에 없는 캐릭터·기능·성과를 발명하지 않는다. 실제 화면을 보지 않았다면
  생성한 UI를 실제 스크린샷이라고 설명하지 않는다.
- 웹 게임·AD·Studio 배지와 사용자 스티커는 사이트가 표시하므로 이미지에 넣지
  않는다. 모서리에 제목·얼굴을 붙이지 않고 배지가 덮일 여유를 둔다.
- 이미지 생성 도구로 제작하고 기존 파일을 임의로 덮어쓰지 않는다. 가능한 경우
  WebP로 저장한다. 실제 출력의 비율·한글 오탈자·얼굴·손·잘림을 확인하고 약
  415×233 카드 크기로 축소해 가독성을 검사한다. 확인하지 못한 항목은 명시한다.
- 결과 경로와 참조 에셋, 적용한 방향을 전달하고 대화로 수정한다. 썸네일 요청만으로
  게임 코드나 시작 화면을 바꾸지 않는다.

## Studio 적용과 게시

Studio 구현은 letscoding_lounge 저장소의 src/features/studio에 있다.
에디터의 프로젝트 문맥과 이미지 생성 도구를 사용하며 터미널이 있다고 가정하지 않는다.
생성 변경안을 반영하고 저장한 뒤 게시 폼의 썸네일에서 해당 파일을 선택한다.

- Studio: 최초에는 **라운지에 게시하기**, 연결된 작품은 **라운지에 변경사항 적용하기**.
  작품 정보·썸네일·게시 설정을 검토하고 기존 작품은 추가·변경·삭제 목록을 확인한다.
  Studio가 내부적으로 ZIP을 만들고 검증·업로드하므로 수동 ZIP 업로드를 요구하지 않는다.
- 외부 프로젝트: 사용자가 ZIP 배포를 요청하면 lounge-deploy 스킬의 최신 정책 조회,
  정적 빌드·검증 절차를 따르고 ZIP과 썸네일을 전달한다. 사용자가 수동 업로드한다.
- 썸네일 생성·파일 저장·ZIP 검증·실제 게시는 별개다. 썸네일 요청은 게시 권한이
  아니며 실제 게시 성공 응답을 확인하기 전에는 게시 완료라고 말하지 않는다.

## 관찰 근거

2026-10-19 lounge.letscoding.kr/works 첫 페이지 40개를 비교했다. 큰 제목과 대표
장면이 반복됐지만 Reading_Log·Testora의 간결한 표지, 도구 화면형, 기본 이미지도
있었다. 따라서 16:9·가독성·작품 정체성을 기본으로 삼되 특정 화풍을 의무화하지 않는다.
