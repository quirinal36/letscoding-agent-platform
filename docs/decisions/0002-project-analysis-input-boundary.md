# 프로젝트 분석 입력 경계

상태: 권장안 적용, 운영자 확인 가능

관련 이슈: #7

## 결정

원격 분석기는 프로젝트 전체 소스를 받지 않는다. 최대 2,000개 파일의 상대 경로와
크기 목록을 기본 입력으로 받고, 내용은 `package.json`, Vite/Next/TypeScript 설정,
그리고 `src/`, `app/`, `pages/`, `public/`, `styles/` 아래의 선택된 텍스트 발췌만
허용한다. 파일별·요청 전체 byte 제한을 함께 적용한다.

`.env*`, lockfile, binary, build 출력 내용은 받지 않는다. lockfile은 존재 여부만
package manager 근거로 사용한다. 결과에는 입력 원문이나 발견한 문자열을 반사하지
않고 안정적인 code, 파일 경로, 고정 문구만 반환한다.

정적 호환성 판정은 구문을 실행하거나 임의 코드를 import하지 않는 보수적인 패턴
분석이다. 확인할 수 없는 설정은 통과로 추측하지 않고 error/recommendation을
반환한다. 서버 기능이 감지된 Next.js 프로젝트는 자동 대체하지 않고 blocker다.

## 대안과 영향

- 전체 repository 업로드는 탐지율을 높일 수 있지만 소스·비밀값 중앙 전송 범위를
  크게 넓힌다.
- AST parser를 프레임워크별로 추가하면 동적 설정 해석이 정교해지지만 parser
  의존성과 언어별 실행 위험, 유지보수 범위가 커진다.
- 로컬 전용 분석만 사용하면 정보 경계는 더 작지만 원격 MCP가 정책 버전별 동일한
  진단 계약을 보장하기 어렵다.

## 사람 확인이 필요한 시점

정상 프로젝트가 발췌 제한 때문에 반복적으로 판정 불가가 되거나 새 지원
프레임워크가 1차 범위에 들어오면 운영자가 allowlist/제한/분석 방식을 승인한다.
외부 API와 루트 절대 URL은 의도된 라운지 API일 수 있으므로 도구가 자동으로
오류 승격하지 않고 사용자의 확인 사유를 요구한다.

## 되돌리기

#7 PR을 revert하면 분석기 패키지와 입력 계약이 함께 제거된다. 입력 범위를 넓힐
때는 기존 제한을 조용히 완화하지 않고 계약 version과 보안 테스트를 같이
변경한다.
